# 🧹 ListenUp! — 클라이언트 리팩터링 보고서

> 대상: `packages/client` · 브랜치: `renew-design`

| 구분 | 내용 |
|------|------|
| 목표 | 거대 컴포넌트 해체 · 관심사 분리 · 타입 안전성 |
| 방식 | Svelte 5 룬 클래스 스토어 + `lib/api` 계층 분리 |
| 대표 성과 | `Game.svelte` **668줄 → 57줄** |

기존 클라이언트는 소켓 연결·이벤트 처리·YouTube 플레이어 제어·화면 렌더링이 한 컴포넌트에 몰려 있었습니다. 이를 **역할별 모듈**로 쪼개고, 서버 통신을 `lib/api`로 분리해 화면 컴포넌트는 "상태를 그리는 일"에만 집중하도록 재구성했습니다.

> ℹ️ 이 문서는 인증·로그인 작업과 별개로 진행된 **클라이언트 구조 개선** 내용만 다룹니다. 인증 관련은 [`인증·로그인 기능 구현 및 배포 보고서`](./인증·로그인%20기능%20구현%20및%20배포%20보고서.md)를 참고하세요.

---

## 1. 리팩터링 원칙

- **관심사 분리(SoC)**: 상태 / 서버로 보내는 요청 / 서버에서 오는 이벤트 / 수명주기 / 외부 SDK 제어를 각각 다른 파일로.
- **화면은 얇게**: `.svelte`는 상태를 읽어 그리고 사용자 입력을 액션에 넘기는 역할만.
- **서버 통신 일원화**: REST는 `lib/api`, 소켓은 `socketEvents` 타입 + 액션/핸들러로.
- **Svelte 5 룬 채택**: `writable` 스토어 → `$state`/`$derived` 기반 클래스 스토어.

## 3. 게임 페이지 해체 (핵심)

기존 `Game.svelte`(약 668줄)에 뭉쳐 있던 로직을 5개 모듈로 분리했습니다.

| 파일 | 책임 |
|------|------|
| `gameStore.svelte.ts` | 연결/방/게임/플레이어 상태를 `$state`로 보유. `isHost`는 `$derived`, `resetRoom()` 제공 |
| `gameActions.ts` | `create-room`, `join-room`, `submit-answer` 등 **서버로 보내는 요청**. 공통 `request()`가 ack 응답을 `AckResponse<T>`로 처리하고 실패 시 `statusMessage`에 반영 |
| `gameSocketHandlers.ts` | `player-joined`, `round-started`, `score-updated` 등 **서버 수신 이벤트**를 스토어에 반영 |
| `gameSession.svelte.ts` | `onMount`에서 소켓 연결·핸들러 등록·YouTube API 로드, 언마운트 시 정리 |
| `youtubePlayer.svelte.ts` | 라운드마다 트랙으로 플레이어 재생성(`$effect`), 음량 동기화, 안전한 파괴(`untrack`) |

그 결과 `Game.svelte`는 스토어와 액션을 가져와 하위 컴포넌트에 넘기는 **57줄짜리 조립 파일**이 되었습니다.

### 개선 포인트 예시
- **점수 갱신**: 기존 배열 직접 변형 → `Map` 조회 + 불변 `map()`으로 교체.
- **플레이어 재생성 무한루프 방지**: `lastLoadedTrackId`로 같은 트랙 재생성 차단, `untrack`으로 이펙트 재트리거 방지.
- **디버그 로그 정리**: 산발적 `console.log`를 `logPlayerState()` 한 곳으로.

## 4. 플레이리스트 페이지 모듈화

| 파일 | 책임 |
|------|------|
| `playlistStore.svelte.ts` | 목록/선택/트랙 상태 + `lib/api` 호출 조율. `run()`으로 loading/error 일괄 관리 |
| `trackSearch.svelte.ts` | 입력 URL에서 비디오 ID 추출 후 트랙 조회 (`TrackSearch` 클래스) |
| `answerList.svelte.ts` | 정답 목록 편집(추가·수정 폼 공용). 항상 최소 한 칸 유지, `filled`로 공백 제외 |

화면 컴포넌트(`Playlist`/`PlaylistForm`/`TrackForm`/`TrackList`)는 이 상태 클래스를 소비만 합니다.

## 5. 서버 통신 계층

### REST — `lib/api`
- `client.ts`: 모든 REST 요청의 공통 진입점. JSON 직렬화, 에러 메시지 추출, 본문 없는 응답 처리.
- `playlists.ts` / `youtube.ts`: 도메인별 엔드포인트 래퍼. `fetchTracks`는 병렬 조회 중 실패한 트랙을 결과에서 제외해 목록 전체가 깨지지 않게 함.

### 소켓 — 타입 안전화
- `socketEvents.ts`: `ServerToClientEvents`(수신 이벤트별 페이로드 타입)와 `ClientToServerEvents`를 정의. 요청 ack는 `AckResponse<T> = ({ success: true } & T) | { success: false; error? }`로 성공/실패를 좁힘.
- `socket.ts`: `Socket<ServerToClientEvents, ClientToServerEvents>` 타입의 `AppSocket`으로 관리.

---

## 6. Svelte 5 룬 전환 & 정리

- 기존 `gameStore.ts`(writable + `updateGameStore()` 패턴) **삭제** → `gameStore.svelte.ts` 클래스 스토어로 대체.
- 모든 상태 클래스는 `$state`/`$derived`, 화면과 무관한 이펙트는 해당 모듈의 `setup...()` 함수에서 `$effect`로 등록.
- `types.ts`로 도메인 타입을 한곳에 모아 서버 응답 형태(직렬화 기준)와 일치시킴.
