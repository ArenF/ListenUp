# 🔐 ListenUp! — 인증·로그인 기능 구현 및 배포 보고서

> 작업일: **2026-08-13** · 브랜치: `renew-design`

| 구분 | 내용 |
|------|------|
| 인증 방식 | 이메일 + 비밀번호 로그인 (JWT) |
| 토큰 저장 | **httpOnly 쿠키** (서버 발급/삭제) |
| 저장소 | SQLite (better-sqlite3) |
| 외부 노출 | Cloudflare Tunnel (HTTPS) |

이번 작업은 로그인 없이 방 코드로만 참가하던 ListenUp!에 **회원가입·로그인·프로필** 기능을 추가하고, 이를 외부에서 접속·테스트할 수 있도록 Cloudflare Tunnel로 노출한 내용을 정리한 것입니다.

---

## 1. 프론트 로그인 프로토타입

기존에 비어 있던 `login/` 페이지를 채우고, 서버의 `/api/auth/*` REST API와 연동했습니다. 기존 `playlistStore`/`gameStore`와 동일한 **Svelte 5 룬 클래스 스토어 + `lib/api` 분리** 컨벤션을 따랐습니다.

| 파일 | 역할 |
|------|------|
| `client/src/lib/api/client.ts` | REST 공통 래퍼 (JSON·에러·credentials 처리) |
| `client/src/lib/api/auth.ts` | `signup` / `login` / `fetchMe` / `logout` |
| `client/src/lib/pages/login/authStore.svelte.ts` | 세션 상태(현재 사용자) 보관·복원 |
| `client/src/lib/pages/login/Login.svelte` | 로그인 ↔ 회원가입 토글 폼 |
| `client/src/lib/pages/login/Profile.svelte` | 프로필 카드 (닉네임·이메일·가입일·로그아웃) |
| `client/src/App.svelte` | `👤 계정` 탭 추가, 로그인 상태에 따라 폼/프로필 자동 전환, 마운트 시 세션 복원 |

## 2. 토큰 저장 → httpOnly 쿠키 전환

초기 프로토타입은 토큰을 `localStorage`에 저장했으나, **XSS 노출 위험**을 없애기 위해 서버가 발급하는 **httpOnly 쿠키** 방식으로 전환했습니다. JS가 토큰을 읽을 수 없고 브라우저가 자동 전송합니다.

**서버**
- `middleware/auth.ts` — `setAuthCookie` / `clearAuthCookie` 헬퍼 추가. 쿠키 옵션 `httpOnly`, `sameSite=lax`, `secure`(운영 환경만). 토큰 추출은 **쿠키 우선, Bearer 헤더 폴백**.
- `routes/auth.routes.ts` — signup/login 시 토큰을 쿠키로 발급하고 응답 본문엔 `user`만. `POST /api/auth/logout` 추가.
- `index.ts` — `cookie-parser` 등록, CORS를 `origin: FRONTEND_URL` + `credentials: true`로 변경.
- `config/env.ts` + `.env.example` — `AUTH_COOKIE_MAX_AGE_DAYS`(기본 7일) 추가.

**클라이언트**
- `api/client.ts` — 모든 요청에 `credentials: "include"`.
- `authStore.svelte.ts` — `localStorage` 제거. `restore()`는 쿠키로 `/me` 호출, 실패 시 비로그인.

## 3. 구조 변경: 아이디 제거, 이메일 로그인

`username`(아이디)과 `email`이 중복이라 판단하여 **이메일을 로그인 ID로 통합**하고 `username`을 전 계층에서 제거했습니다.

**최종 사용자 모델**: `email`(고유·로그인 ID) + `password` + `nickname`(표시용, 비우면 이메일 앞부분 자동)

| 계층 | 변경 |
|------|------|
| 서버 타입 | `UserRecord`/`PublicUser`에서 `username` 제거, JWT 페이로드 `{ sub, email }` |
| DB 스키마 | `users`에서 `username` 컬럼·인덱스 제거 (이메일만 UNIQUE) |
| 레포지토리 | `findByUsername` 삭제 → `findByEmail`이 로그인·중복체크 겸용 |
| 서비스 | 이메일로 로그인/중복체크, `USERNAME_REGEX` 삭제, 닉네임 기본값 = 이메일 로컬파트 |
| 클라이언트 | `Login.svelte` 아이디 입력칸 삭제, `Profile.svelte` `@username` → 이메일 표시 |

> DB는 구 스키마(`username NOT NULL`)와 충돌하므로 기존 파일 삭제 후 새 스키마로 재생성했습니다. `*.db`는 gitignore 대상이라 저장소엔 영향 없음.

## 4. Cloudflare Tunnel 외부 배포

라우터 설정 없이 HTTPS로 외부 접속을 열기 위해 Cloudflare Tunnel을 사용했습니다.

```
브라우저 (https://*.trycloudflare.com)
   → cloudflared 터널
   → localhost:5173 (Vite dev, /api·/socket.io 프록시)
   → localhost:3000 (Node 서버)
```

- 브라우저 입장에서 전부 **동일 오리진**이라 CORS·쿠키가 그대로 동작.
- `vite.config.ts`에 `allowedHosts` 추가 (Vite의 낯선 호스트 차단 해제).
- 외부 노출 전 `JWT_SECRET`을 강한 랜덤 값으로 교체(`.env`, gitignore 대상).

## 5. 트러블슈팅

### 5-1. 낡은 `vite.config.js`가 `.ts`를 가림 (403의 진범)
외부 접속이 `403 Blocked request: This host is not allowed`로 막혔는데, 에러 메시지가 `vite.config.**js**`를 가리켰습니다. Vite는 config 확장자에서 `.js`를 `.ts`보다 먼저 로드하는데, `tsc`(composite 프로젝트)가 `vite.config.ts`에서 생성한 낡은 `vite.config.js`에는 `allowedHosts`가 없어 `.ts` 수정이 무시되고 있었습니다.
→ 산출물 삭제 후 해결. 재발 방지를 위해 `vite.config.js`/`vite.config.d.ts`를 **`.gitignore`에 추가**.

### 5-2. `.test` 도메인은 외부 라우팅 불가
네임드 터널의 공개 호스트명으로 `.test` TLD를 시도했으나, `.test`는 RFC 6761 예약 TLD라 공용 DNS에 존재할 수 없어 도달 불가. 도메인이 없는 경우 퀵 터널(`trycloudflare.com`)이 정답.

### 5-3. 마이그레이션 과도기 DB 제약 오류
`tsx watch`가 코드 변경 시 자동 재시작되는데, 구 DB(`username NOT NULL`)가 남아 있어 새 INSERT가 `NOT NULL constraint` 오류를 냄. DB 파일 재생성으로 해소.

## 🔭 남은 과제 / 주의

- **CSRF**: httpOnly 쿠키는 CSRF에 노출됨. 현재 `sameSite=lax` + POST로 기본 방어는 되나, 운영에선 CSRF 토큰 권장.
- **퀵 터널 URL**은 cloudflared 재시작 시 변경됨. 고정 URL은 Cloudflare에 등록된 실제 소유 도메인 필요.
- **영구 실행**: 재부팅 후 자동 실행은 관리자 권한으로 `cloudflared service install <토큰>`.
- **프로덕션 정적 서빙** 시 `npm run build:client`로 최신 로그인 화면 반영 필요.
- 아바타는 URL이 있으면 이미지, 없으면 이니셜 표시 (업로드 UI 미구현).
