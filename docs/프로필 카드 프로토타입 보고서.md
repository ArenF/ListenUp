## 1. 왜 수집형 카드인가

- **차별점**: 대부분의 스탯 카드는 숫자 나열에 그친다. 음악 게임은 "취향(최애 장르·플레이리스트)"이라는 사람 냄새 나는 축이 있어, 이를 카드에 녹이면 이 앱만의 개성이 된다.
- **자랑 동기**: 대표 스탯 1개를 압도적으로 크게 보여줘 "이 사람 = 이 숫자" 로 각인.
- **수집 욕구**: 티어별로 카드 프레임(색·광택)이 바뀌어 등급을 올리고 싶게 만든다.
- **바이럴 훅**: (후속) 카드를 이미지로 내보내 공유 → 유입 경로.

## 2. 스탯 구성

대표 스탯 1개 + 보조 4개 + 취향 1개 구조. **볼드 항목은 게임에 이미 존재하는 개념**(`streak`, `GameResult.winner`, `correctAnswers/totalRounds`)이라 데이터만 저장하면 바로 채울 수 있다.

| 위치 | 스탯 | 근거 데이터 | 현재 |
|------|------|-------------|------|
| 대표(크게) | 🔥 **최고 연속 정답(Best Streak)** | `streaks` (게임 중 존재) | mock 27 |
| 보조 | 🎮 플레이한 게임 수 | 집계 필요 | mock 128 |
| 보조 | 🏆 **승률** | `GameResult.winner` | mock 63% |
| 보조 | 🎯 **정답률** | `correctAnswers / totalRounds` | mock 71% |
| 보조 | ⚡ 최속 정답 | 라운드 응답시간(미저장) | mock 1.4s |
| 취향 | 🎵 최애 장르/플레이리스트 | 플레이 이력 | mock "K-POP" |
| 파생 | 레벨 · 티어 · 칭호 | 위 스탯 조합 | mock Lv.42 / 장르 마스터 |

## 4. 디자인 언어

기존 웜톤 정체성(`#ff3e00`)을 유지하되, **티어를 카드의 재질/색으로 시각화**한 것이 핵심.

- **티어 프레임 4종** — 레벨 기준 자동 선택 (`tier` 파생값)
  | 티어 | 조건(레벨) | 프레임 |
  |------|-----------|--------|
  | BRONZE | < 10 | 무광 베이지 |
  | SILVER | 10~24 | 메탈릭 그레이 |
  | GOLD | 25~39 | 골드 그라디언트 + 광택 스윕 |
  | MASTER | ≥ 40 | 홀로그램(핑크·블루·민트) 그라디언트 + 광택 스윕 |
- **광택 스윕**: gold·master는 `@keyframes sweep`로 하이라이트가 카드 위를 흐른다.
- **hover 3D tilt**: 마우스 위치에 따라 `perspective + rotateX/Y`로 카드가 기울어져 수집 카드 손맛.
- **대표 스탯 강조**: 나머지 숫자의 2~3배 크기.
- **모바일 대응**: 420px 이하에서 히어로 세로 정렬, 스탯 글자 축소.
- 우상단 **`MOCK` 리본**: 아직 가짜 데이터임을 명시(실제 연동 시 제거).

## 5. 구현 메모

- 스탯은 스크립트 상단 **`const stats = { … }` 한 곳에 모아** mock으로 선언. 주석으로 교체 지점(`GET /api/users/:id/stats`)을 명시해, 백엔드 연동 시 이 객체만 실제 응답으로 바꾸면 된다.
- `tier`는 `$derived.by`로 레벨→등급 환산. 티어 `key`가 카드 `class`로 붙어 프레임 CSS를 선택.
- 회원번호(`memberNoDisplay`)는 기존 로직 유지(유저 ID 앞자리를 `LU-XXXX-XXXX` 형태로 정리).
- 아바타 변경·로그아웃 섹션은 **실제 기능 그대로 유지**, 카드 부분만 리디자인.

## 🔭 남은 것

프로토타입은 UI까지. 실제 서비스가 되려면 **데이터를 남기는 일**이 선행되어야 한다.

1. **백엔드 스탯 저장** — `user_stats` 테이블 추가(`gamesPlayed, wins, correctAnswers, totalRounds, bestStreak, favoritePlaylistId`). 게임 종료(`handleNextRound` 게임 엔딩 / `handleForceEndGame`) 시점에 참가자별 누적 업데이트. 최속 정답 스탯을 원하면 라운드 정답 제출에 타임스탬프 저장.
2. **조회 API** — `GET /api/users/:id/stats` (내 프로필은 로그인 유저).
3. **카드 연동** — mock `stats` 객체를 API 응답으로 교체, `MOCK` 리본 제거, 티어 산식 확정.
4. **확장** — 업적 뱃지/칭호, 카드 이미지 내보내기(html-to-image) + SNS 공유.
