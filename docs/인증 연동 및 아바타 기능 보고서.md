앞선 작업으로 로그인/회원가입은 만들었지만 게임·플레이리스트와 분리돼 있었습니다. 이번엔 로그인 정체성을 실제 기능에 연결하고, 사용자별 아바타를 도입했습니다.

> ℹ️ 인증 기반 구축(이메일 로그인·httpOnly 쿠키)은 [`인증·로그인 기능 구현 및 배포 보고서`](./인증·로그인%20기능%20구현%20및%20배포%20보고서.md) 참고.

## 1. 게임에서 로그인 정체성 사용

- `Game.svelte`: `$effect`로 로그인 시 게임 닉네임을 계정 닉네임으로 자동 고정.
- `GameLobby.svelte`: 로그인 상태면 닉네임 입력칸 대신 **`계정 닉네임 + [로그인 계정] 뱃지`**를 잠금 표시. 비로그인은 게스트 입력 유지.

## 2. 플레이리스트 관리 로그인 게이팅

- `App.svelte`: 비로그인으로 플레이리스트 탭 진입 시 **🔒 로그인 안내 + "로그인하러 가기"**. 로그인해야 관리 화면 노출.

## 3. 플레이리스트 소유권 (공유 + 작성자 권한)

모두가 모든 플레이리스트를 **조회·게임 사용**할 수 있고, **수정·삭제·트랙 편집은 작성자만** 가능한 모델.

**서버**
- `Playlist`에 `ownerId` / `ownerNickname` 추가. 생성 시 로그인 사용자를 작성자로 등록.
- 생성/수정/삭제/트랙 라우트에 `requireAuth` + `checkPlaylistOwner()` 적용.
  - 타인 → 403, `ownerId` 없는 **기본 제공 플레이리스트 → 403**(아무도 수정 불가).
- 조회(`GET`)는 공개 유지.

**클라이언트**
- `Playlist.svelte`: 작성자 본인에게만 수정/삭제/트랙편집 버튼 노출, 그 외 조회 전용.
- 헤더 라벨: `🎵 기본 제공` / `👤 내 플레이리스트` / `👤 by 닉네임`.
- `TrackList.svelte`: `canEdit` prop으로 트랙별 편집 버튼 제어.

| 시나리오 | 결과 |
|---|---|
| 비로그인 생성 | 401 |
| 작성자 생성 | 201(+소유자 기록) |
| 타인 수정/삭제 | 403 |
| 작성자 수정 | 200 |
| 기본 제공 수정 | 403 |
| 비로그인 목록 조회 | 200 |

## 4. 아바타 (기본 프리셋 + 파일 업로드)

계정 아바타는 **이미지 URL 문자열**로 저장한다(파일 바이너리는 DB에 넣지 않음).

**기본 프리셋 3종**
- `packages/client/public/avatars/avatar-1~3.png` (악어 / 치킨 / 늑대) → Vite가 `/avatars/...`로 서빙.
- 목록은 `client/src/lib/avatars.ts` · `server/services/auth.ts`의 `DEFAULT_AVATARS`에 동일하게 정의.
- **회원가입 시 셋 중 하나 랜덤 배정**.

**프로필에서 변경** (`Profile.svelte`)
- 프리셋 3개 클릭 선택(선택 항목 테두리 강조).
- 이미지 파일 업로드(PNG/JPG/WebP/GIF, **최대 5MB**).

**서버**
- `PATCH /api/auth/me` — 닉네임/프리셋 아바타 수정(프리셋 목록만 허용, 외부 URL 차단).
- `POST /api/auth/avatar` — `multer` 디스크 저장 → `/api/uploads/avatars/<파일>` URL로 avatar 갱신.
- `/api/uploads` 정적 서빙(기존 `/api` 프록시 재사용). 업로드 폴더는 gitignore.
- `userRepository.update` + `authService.updateProfile` 추가.

| 시나리오 | 결과 |
|---|---|
| 가입 → 기본 아바타 랜덤 배정 | 프리셋 URL |
| 프리셋 변경(PATCH) | 200 |
| 허용 외 외부 URL | 400(차단) |
| 파일 업로드 → 서빙 | 200, image/* |
| 새로고침(쿠키 `/me`) 유지 | 유지됨 |
| 5MB 초과 업로드 | 400 "파일이 너무 큽니다 (최대 5MB)" |

## 🔭 남은 것
- **게임 방에 계정 아바타 표시**: 현재 게임 플레이어 아바타는 서버가 배정하는 이모지(`room.ts`)로, 계정 아바타(URL)와 별개. 연동하려면 `GameRoom`이 "URL이면 `<img>`, 이모지면 텍스트"로 분기 + `create/join` 페이로드에 아바타 전달 필요.
- 프로필 닉네임 편집 UI(엔드포인트 `PATCH /me`는 이미 지원).
- 보안 하드닝(CSRF 토큰, 인증 엔드포인트 rate limit).
